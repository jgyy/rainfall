## Level2 Binary Analysis and Exploitation

### Quick Facts
- Binary: /home/user/level2/level2
- Type: ELF 32-bit Intel x86
- Permissions: -rwsr-s---+ (setuid level3)
- Vulnerability: Buffer overflow in p() function via gets() + Address check bypass using RET gadget

### Vulnerability Overview
The p() function has two protections:
1. Buffer overflow via gets() - classic stack overflow
2. Return address validation check that blocks 0xb0xxxxxx addresses (libc)

The trick: Direct ret2libc is blocked, but ret2ret (return to a RET gadget) works!

### Stack Layout in p()
- Function allocates 104 bytes on stack (sub $0x68)
- Buffer at EBP-0x4c (76 bytes)
- Return address at EBP+4
- Local variable at EBP-0xc stores copy of return address for validation

### The Security Check
```
80484f2:	8b 45 04             	mov    0x4(%ebp),%eax    # Load return address
80484f5:	89 45 f4             	mov    %eax,-0xc(%ebp)   # Save to local var
80484f8:	8b 45 f4             	mov    -0xc(%ebp),%eax   # Reload it
80484fb:	25 00 00 00 b0       	and    $0xb0000000,%eax  # Mask high bits
8048500:	3d 00 00 00 b0       	cmp    $0xb0000000,%eax  # Check for libc range
8048505:	75 20                	jne    8048527           # If NOT libc, continue
```

If (returnAddress & 0xb0000000) == 0xb0000000, print "Nope" and exit.
Otherwise, continue execution.

### Why Standard Ret2Libc Fails
- Can't jump to system() at 0xb7e6b060 because (0xb7e6b060 & 0xb0000000) == 0xb0000000
- The check blocks the entire libc address range

### The RET Gadget Bypass (Ret2Ret)
The check only validates the FIRST return address. The trick:
1. Overflow buffer to jump to a RET gadget in the binary code (0x0804853e)
2. This passes the check: (0x0804853e & 0xb0000000) = 0
3. The RET instruction at 0x0804853e pops the next value from stack into EIP
4. The next value on stack is system()'s address - executed WITHOUT validation!

### Payload Structure (80 bytes total)
```
Offset 0-75:   [76 bytes] = "A" * 76                    # Padding
Offset 76-79:  [4 bytes]  = 0x0804853e (RET gadget)     # First return address
Offset 80-83:  [4 bytes]  = 0xb7e6b060 (system addr)    # Popped by RET
Offset 84-87:  [4 bytes]  = 0xb7e5ebe0 (exit addr)      # Return value for system
Offset 88-91:  [4 bytes]  = 0xb7f8cc58 ("/bin/sh")      # Argument to system
```

### Gadget Discovery
Located RET instruction at 0x0804853e in the p() function:
```
804853d:	c9                   	leave
804853e:	c3                   	ret
```

### Libc Address Discovery
Must find at runtime since ASLR is disabled but libc can still vary:
- system() - needed for execution
- exit() - return address
- "/bin/sh" string pointer - argument to system

### Attack Sequence
1. Connect to level2 via SSH using level1's password
2. Create overflow payload with RET gadget
3. Pipe payload to level2 binary
4. Shell spawns with level3 privileges
5. Read /home/user/level3/.pass

### Key Insight
The security developer forgot that after returning from overflow, the *next* return instruction isn't checked. By chaining RET gadgets, we bypass the filter completely. This is a classic ROP (Return Oriented Programming) technique.

### Environment Info
- ASLR: Disabled
- NX: Disabled (stack executable)
- Kernel: Linux 2.6.24+
- Libc: glibc 2.15
- Architecture: i386
